# Захист проєкту: модуль `log3.defense` і сценарії учасників

## Запуск

```bash
python -m log3.defense --list                         # етапи, профілі, вид кожного етапу
python -m log3.defense                                # quick: ~10–15 хв, автоматично
python -m log3.defense --profile full                 # усі тести, нові експерименти, уся матриця, інсталяція
python -m log3.defense --stage showcase --step        # покроково: Enter перед кожною командою
python -m log3.defense --stage matrix --profile full  # лише матриця відмов (9 сценаріїв)
python -m log3.defense --profile full --dry-run       # план: усі команди без виконання
```

Для кожного кроку модуль друкує мету, фактичну команду (секрети замінено на `***`), живий вивід, тривалість,
код завершення й перевірений результат (перевірка читає вивід або стан на диску). Підсумок:
`defense-out/defense-<час>.log` (повний вивід без секретів) і `defense-<час>.json` (машинозчитуваний).
Код модуля 0 — усі кроки пройдено, 1 — є провали.

**Що як позначено.** `новий експеримент` — рахує заново в ізольованій копії проєкту (закомічені `results/`,
модель і `materials/` не перезаписуються; перевіряється SHA-256 до й після); `перегляд збережених` —
показ закомічених чисел із комітом останньої зміни; `dev-режим` — без `materials/` (синтетичний конфіг і
модель відмов, не дані викладача); `продукт` — LOG3 Vault у тимчасовому каталозі. Продуктові процеси працюють
на одному диску: це демонстрація процесних і мережевих відмов, а не незалежних фізичних дисків.

| Етап | Що показує |
| :-- | :-- |
| env | версії, ruff, pytest (quick — вибірка, full — увесь набір) |
| pipeline | навчальний тракт у трьох сценаріях, S/R/T/Q у навчальних одиницях |
| huffman | канонічний Гаффман (decode = вхід, Крафт = 1), ДП = повний перебір ≥ жадібний, тести |
| classifier, ga | quick — збережені метрики; full — нове навчання / новий пошук в ізольованій копії |
| attack | ГА відновлює ключ слабкого шифру, змінені репліки відхиляються |
| vault-mixed | змішаний каталог: backup → find → restore побайтово → drill → Prometheus |
| showcase | вузол недоступний → стійке приймання → аварія процесу → черга з диска → вузол повернувся → `protected` → verify → restore побайтово |
| node-repair | пошкодження й втрата копій → verify (код 7) → repair → restore; маніфест без цілих копій → відмова без часткових файлів |
| learning | холодний старт → train → shadow-оцінка → promote → restore → rollback |
| keys | ротація, зміна фрази, стара версія новою фразою, експорт, `log3_restore.py` через `python -I` без пакета |
| update | справжня версія етапу 2 з git: аварія міграції → стара версія працює → успішна міграція |
| install (full) | реліз → SHA256SUMS (і виявлення підміни) → чистий venv → офлайн-встановлення → backup/restore |
| matrix:* | 9 сценаріїв відмов, [GUARANTEES.md](GUARANTEES.md) |

## Сценарії учасників (по 5 хвилин)

**Гліб Степанов ([@Galactic717](https://github.com/Galactic717)) — формат LOG3, захист, інтеграція; етап 3.**
Показ: `python -m log3.defense --stage showcase --step`, потім `--stage keys` і рядок підсумку матриці.
Пояснити: різниця `accepted_local` / запис копії / `protected` ([GUARANTEES.md](GUARANTEES.md) §1); чому
`run` не потребує фрази; що бачить вузол ([SECURITY.md](SECURITY.md) §4). Питання: «що буде при втраті
живлення?» — гарантія лише за чесного `fsync`, фізично не перевірено; «чому не 0 втрат?» — версії до
`protected` гинуть разом із локальним диском.

**Ярослав ([@yaroslavronenko-ux](https://github.com/yaroslavronenko-ux)) — Гаффман, ДП, розміщення;
етап 1 (файлове ядро, черга, реплікація, restore).** Показ: `--stage huffman`, `--stage node-repair`.
Пояснити: канонічний код і package-merge (`log3/huffman.py`), ДП O(n·W·R) проти жадібного, модель станів
(`log3/vault/states.py`), ідемпотентний `job_id` і перевірку підтвердження (`backends/base.py`).
Питання: «чому подвійний PUT не списує квоту двічі?» — облік вузла за `oid`.

**Артем ([@artemkovbasuk780-hub](https://github.com/artemkovbasuk780-hub)) — перцептрон, ГА,
атака; етап 2 (локальне навчання).** Показ: `--stage classifier --stage ga --stage attack --stage learning`
(у full — нові експерименти). Пояснити: вікно історії й абляцію, ГА проти random search за однакового
бюджету, gate shadow → active і rollback ([LEARNING.md](LEARNING.md)); restore не залежить від моделі.
Питання: «чому модель не активується автоматично?» — у вимірах вона не перевершила базу.
